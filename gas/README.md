# 和煎｜結帳串接 Google Sheet 部署步驟

## 架構

```
網站結帳（index.html）
   │  POST 訂單 JSON（text/plain，免 CORS 預檢）
   ▼
Google Apps Script 網頁應用程式（Code.gs → doPost）
   │  驗證資料 → 依「商品」表重算金額 → 產生單號 → 寫入
   ▼
Google 試算表：訂單｜訂單明細｜商品｜每日統計
   └─ 寄「新訂單通知」給店家、「訂單確認信」給顧客
```

## 一、建立試算表與 Apps Script

1. 到 Google 雲端硬碟，建立新的試算表，命名為「和煎 訂單」。
2. 點選上方選單「擴充功能 → Apps Script」。
3. 把編輯器裡原本的 `Code.gs` 內容全部刪掉，貼上本資料夾的 `Code.gs`，然後存檔。
4. （選用）點左側「專案設定 ⚙」，勾選「在編輯器中顯示 appsscript.json」，再貼上本資料夾的 `appsscript.json`，時區就會設成台北。
5. 視需要修改 `Code.gs` 最上方的 `CONFIG`：
   - `NOTIFY_EMAIL`：新訂單要通知的信箱（留空就寄給你自己）
   - `SEND_CUSTOMER_EMAIL`：是否寄確認信給顧客
   - `SHIPPING_FEE`、`STORES`：運費與門市，必須和網站上的一致

## 二、初始化工作表

1. 在上方函式選單選 `setup`，按「執行」。
2. 第一次執行會要求授權：選你的 Google 帳號 → 進階 →「前往（不安全）」→ 允許。
3. 回到試算表，會看到 4 個分頁：**訂單、訂單明細、商品、每日統計**。
4. 選 `testOrder` 按執行，會新增一筆測試訂單，你也會收到通知信。確認沒問題後，把那筆測試資料刪掉即可。

## 三、部署成網頁應用程式

1. 點右上角「部署 → 新增部署作業」→ 齒輪選「網頁應用程式」。
2. 執行身分：**我**；誰可以存取：**所有人**。
3. 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。
4. 用瀏覽器打開這個網址，看到 `{"ok":true,...}` 就代表成功。

## 四、接上網站

打開 `index.html`，找到這一行：

```js
const ORDER_API_URL = '';
```

把剛剛複製的網址貼進引號裡，commit 並推上 GitHub，GitHub Pages 更新後就完成了。
（留空的話，網站會維持原本的模擬結帳。）

## 日常使用

- **訂單狀態**：在「訂單」表的「狀態」欄用下拉選單切換：新訂單 → 製作中 → 可取餐/已出貨 → 已完成（或已取消）。
- **改價格、下架商品**：直接修改「商品」表。伺服器一律用這裡的單價計算金額，網站上的價格也記得一起改。
- **每日營收**：看「每日統計」分頁，會自動排除已取消的訂單。

## 修改程式後要重新部署

修改 `Code.gs` 之後，要到「部署 → 管理部署作業 → ✏️ 編輯 → 版本：新版本 → 部署」。
這樣網址不會變，網站不用改。如果選「新增部署作業」，會產生新網址，網站就要跟著換。

## 安全設計

- 金額、運費都在伺服器端重新計算，前端傳來的金額不會被採用。
- 同一筆訂單重複送出（連點、網路重試）只會建立一次（6 小時內）。
- 以 LockService 避免同時下單時單號重複；單號依日期流水編號：`HJ-20261128-0001`。
- 會擋掉試算表公式注入（例如以 `=`、`+` 開頭的輸入），並設有隱藏欄位防機器人。
- 顧客資料只寫進你自己的試算表；網址公開也不會讓任何人讀到訂單內容（doGet 只回傳健康檢查）。

## 限制

- 不含線上付款，屬於到店或貨到付款模式。要接金流（綠界、LINE Pay 等）需要另外串接。
- Gmail 個人帳號每天約可寄 100 封信，Workspace 帳號約 1,500 封。
